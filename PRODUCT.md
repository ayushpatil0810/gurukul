# Product

## Register

product

## Users

Students learn a concept, then practice it. Trainers author the concept map, questions, and lessons for their batches. Institute admins stay inside their own institute. The job on a lesson screen is to understand one concept, not to manage a course catalog.

## Product Purpose

The portal chooses the next coding question from a prerequisite graph and a stored mastery estimate. Lesson Studio adds a trainer-written explanation for the concept the selector already chose. Reading a lesson does not change mastery, a hidden-test score, or an integrity signal.

## Brand Personality

Direct, calm, and specific. The interface should sound like a teacher explaining one idea, and look like a tool the same person already uses for practice.

## Anti-references

Generic AI dashboards, glowing cards, glassmorphism, and pages that treat every scene as the same paragraph. Do not present viewing progress as mastery.

## Design Principles

1. Show the working path: requirements, outline, scenes, preview, then publish.
2. Say what is stored and what is only a prediction.
3. Keep drafts private and answers off the student view.
4. Use the portal's existing type, color, and controls.
5. Refuse content the schema cannot render safely.

## Accessibility & Inclusion

Body text stays on the existing ink color so it remains readable on the white surface. Controls use visible focus. Motion is limited to state changes. Explanations default to English. A programming language in an example is not a claim that the assessment runner can execute it.
