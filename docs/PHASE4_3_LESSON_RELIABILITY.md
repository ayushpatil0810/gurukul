# Phase 4.3 — Lesson Repair, End-to-End Reliability & Demo Readiness

This document records the findings, fixes, end-to-end verification, and regression coverage for Phase 4.3 of the Adaptive Learning and Assessment Portal.

## 1. Root Cause of Existing TypeScript Lesson Defect

**Existing Lesson:** `TypeScript Return Values` (`e9434b61-2069-43ff-a805-66ca98f78f27`) on concept **Functions**.

### Findings
1. **Scene 3 (`scene_3`, "Return Types in TypeScript")**:
   - The scene contained non-English Chinese labels generated by OpenMAIC's underlying slide template:
     - `"位置"` (Where it goes)
     - `"参数列表后面"` (After the parameter list)
     - `"常见类型"` (Common types)
     - `"作用"` (What it does)
     - `"返回值必须匹配声明类型"` (The returned value must match the declared type)
     - `"示例"` (Example)
   - In addition, the TypeScript code block in Scene 3 had an unclosed function body (`function add(a: number, b: number): number { return a + b;` missing the closing `}`).
2. **Scene 6 (`scene_6`, "Reading Simple Examples")**:
   - The scene included a C/Java style function definition: `int add(int a, int b) { return a + b; }`.
3. **Validation & Republication Behavior in Phase 4.2**:
   - In Phase 4.2, `inspectLesson` was configured with `unexpectedScript` (rejecting CJK, Hangul, Katakana, Hiragana) and `foreignDeclaration` (rejecting C/Java primitive types in TS/JS), as well as TypeScript syntactic diagnostics.
   - While `inspectLesson` successfully blocked any attempt to republish the defective lesson, the existing published row in the database still stored the invalid content, exposing it to learners unless repaired.

### Repair Mechanism
- Applied targeted phrase repair via `applyPhraseRepair` in `saveRepairedLesson` (`lib/services/lessons.ts` & `lib/engine/lesson-repair.ts`).
- Exact phrases were mapped to English equivalents without modifying unaffected scenes (`scene_1`, `scene_2`, `scene_4`, `scene_5`, `scene_7`, `scene_8` remained byte-for-byte identical).
- Scene 3 was updated with `"Where it goes"`, `"After the parameter list"`, `"Common types"`, `"What it does"`, `"The returned value must match the declared type"`, `"Example"`, and the closing brace `}`.
- Scene 6 was updated to `function add(a: number, b: number): number { return a + b; }`.
- Post-repair validation with `validateScene` and `inspectLesson` confirmed **0 blocking errors**.

## 2. Root Cause of JavaScript Generation Failure

**Existing Draft:** `Async and Await Basics` (`83394199-a40e-4e10-a273-186dddb3eee0`) on concept **Functions** with code language **JavaScript**.

### Findings
1. **Language Prompt Ambiguity**:
   - `languagePrompt("javascript")` in `lib/engine/lesson-languages.ts` originally stated `Do not use C or Java declarations such as "int add"`, but did not explicitly prohibit TypeScript type annotations or interfaces in JavaScript lessons.
   - LLMs frequently generate return type annotations (e.g. `async function getValue(): Promise<number> { return 42; }`) when generating async code.
2. **TypeScript Parser Diagnostics for JavaScript**:
   - `checkCodeSyntax` checks `.js` code with `ScriptKind.JS` and `allowJs: true`. TypeScript's parser treats type annotations in `.js` files as syntactic errors: `"Type annotations can only be used in TypeScript files."`
3. **Repair Instruction Language Context**:
   - `repairInstruction` originally produced generic instructions (`"Replace this example with valid code and keep the explanation in English:"`) without reminding the model of the selected programming language.
4. **Failure Behavior**:
   - When attempt 1 failed with TypeScript annotations or invalid syntax in `Async Functions Return Promises`, attempt 2 failed closed because the retry prompt did not reinforce plain JavaScript rules.

### Implemented Fix
1. **Explicit Language Directive in `languagePrompt`**:
   Updated `lib/engine/lesson-languages.ts`:
   ```ts
   code === "javascript"
     ? `Each JavaScript example must be syntactically valid plain JavaScript. Do not use TypeScript type annotations or interfaces, and do not use C or Java declarations such as "int add".`
     : ...
   ```
2. **Language-Aware `repairInstruction`**:
   Updated `repairInstruction` in `lib/engine/lesson-generation.ts` to accept the target code language and generate language-specific repair instructions:
   ```ts
   Replace this example with valid JavaScript and keep the explanation in English:\n<sample>
   ```
   Passed `language.code` from `requestOneScene` into `repairInstruction`.
3. **Bounded Scene Repair**:
   - Preserves existing attempt limit (`sceneAttempts = 2`).
   - If attempt 1 fails syntax or language checks, attempt 2 provides the concise validation error, target language, and original snippet.
   - Fails closed with `AppError.badRequest("... The draft was not changed.")` if the repair limit is reached without altering previously saved drafts.

## 4. Repair and Publication Behavior

1. **Publication Safety**:
   - Stored lessons enforce optimistic concurrency control via `version` column (`where id = row.id and version = version`).
   - `saveRepairedLesson` updates the published row only if:
     - All phrase replacements succeed in the target scene.
     - `@openmaic/dsl` `validateScene` passes for all scenes.
     - `inspectLesson` reports zero `error` severity issues.
   - If repair or validation fails, no changes are committed to PostgreSQL, and an actionable error is returned.
2. **Rollback & Draft Protection**:
   - Updating or generating scenes in a published lesson requires re-asserting zero blocking errors before saving.
   - If generation of a scene fails, previously saved scenes in the draft are left untouched.
3. **Draft Privacy**:
   - Draft lessons (`status === 'draft'`) are hidden from students (`readLessonForStudent` throws 404).
   - Only published lessons are accessible to students, and only when the lesson's concept matches the student's currently recommended concept.

## 5. Language-Validation Limitations

1. **Explanations**:
   - English only (`explanation=en`). Rejects CJK (`\u3400-\u9fff`), Kana (`\u3040-\u30ff`), and Hangul (`\uac00-\ud7af`).
   - Hindi is unsupported.
2. **Code Syntax Verification**:
   - **TypeScript & JavaScript**: Syntactically parsed with `typescript` compiler host (`ts.createProgram` with `getSyntacticDiagnostics`).
   - **Java & C++**: Syntax is **NOT** checked in Lesson Studio. They are labeled as unverified warnings.
3. **Runtime Execution**:
   - **No code is executed on the application server during lesson validation or preview.**
   - Syntax validation confirms grammatical correctness only; it does not verify runtime semantics, infinite loops, or behavioral correctness.
